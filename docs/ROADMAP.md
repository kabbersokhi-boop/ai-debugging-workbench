# Roadmap

Patch Audit currently provides saved-result walkthroughs, prepared local Python and Node audits, reusable project checklists, browser and terminal workflows, readable reports, and generated inputs for supported Python functions.

The recorded viewer is public. Running a new patch remains a private local operation.

## Next steps

- Observe developers using the prepared workflow without coaching. Measure setup, execution and result inspection separately, including failed and unsupported attempts.
- Fix problems demonstrated by those sessions, then repeat the affected tasks.
- Evaluate more independently sourced changes before making broader usefulness or accuracy claims.
- Improve loading and code-comparison performance where measurements show a problem.

Support for more input shapes or languages needs explicit requirements, passing/failing examples and a new version of any changed verification behavior. Existing evidence must remain readable.

Public execution is not part of the current product. It would require a separate design and isolation review.

Earlier debugging and repair experiments remain documented in the [technical references](README.md#research-and-technical-references). Their original results and limitations are preserved.
